I built Interview Handbook because I watched myself (and everyone around me) waste hours on interview prep that didn't stick. The problem wasn't effort — it was the method. We were memorizing solutions instead of learning patterns.

## Why memorizing fails

A random problem teaches you one answer. But interviews don't ask the problems you've seen; they ask variations. Memorizing solutions means you panic the moment something looks unfamiliar — which is exactly what the interview tests.

## What a pattern actually is

A pattern is a *shape of solution* that applies to many problems. Learning "two pointers" isn't learning one problem — it's learning a tool you can reach for whenever you see a sorted array.

## The pattern-first framework

This is the core of the method:

1. **Learn the pattern** — the template and the intuition behind it
2. **See it in a few problems** — how the pattern manifests
3. **Recognize it in new problems** — the "signal" that this is a two-pointer problem

The third step is the skill that matters, and it only comes from exposure to many problems *grouped by pattern* — not scrambled randomly.

## The signal-to-pattern mapping

The key move is translating problem language into a pattern:

| Problem signal | Likely pattern |
|----------------|----------------|
| Sorted array, find pair | Two pointers |
| Subarray / substring | Sliding window |
| Cycle in a linked list | Fast & slow |
| "Does it exist?" | Hash map |
| Sorted data, find value | Binary search |
| Min / max / number of ways | Dynamic programming |

## Practice grouped by theme

Don't do "day 3 of random problems." Do "this week: sliding window." Solve five problems all using sliding window. You'll see the pattern clearly, and when it shows up in the interview, you'll recognize it instantly.

## Why it works

Interviews reward recognition, not recall. When you see the pattern beneath a problem, you don't solve it from scratch — you remember the approach and adapt. That's faster, calmer, and far more impressive.

Learn the patterns. The problems will take care of themselves.
